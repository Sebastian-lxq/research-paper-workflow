# Capability and claim boundaries

This project separates three questions that are often conflated:

1. **Is the controller structurally valid?** A schema, manifest, or state file
   can answer this.
2. **Did the tested behavior occur in the recorded case?** A regression or
   forward test can answer this within its fixture scope.
3. **Is the scientific conclusion true and general?** Only task-specific source,
   proof, data, simulation, and independent-review evidence can answer this.

## Supported v0.1.0 claims

The public package may claim that it supplies:

- explicit stage dependencies and resumable, hash-bound receipts;
- tested controllers for workflow state, revisions, idea portfolios, empirical
  contracts, offline operations, and token/quality comparisons;
- a wait barrier that prevents result-dependent work from advancing while an
  offline job is still running;
- rules that constrain novelty and completion language when evidence is missing.

Each claim is limited to the bundled implementation and recorded test cases.

## Claims the project must not make

The project does not establish that:

- a literature search covers every influential journal or every relevant paper;
- a candidate idea is globally novel;
- an econometric theorem or proof is correct;
- an empirical design is identified;
- a simulation result is accurate without its own numerical audit;
- a manuscript is publishable or will be accepted;
- every iteration improves every dimension;
- token use falls without a paired, comparable measurement;
- local tests imply second-host or cross-project portability.

## Evidence required before stronger claims

- **Portability:** a clean install and complete check on a second supported host.
- **Cross-project behavior:** a frozen second-paper holdout distinct from the
  calibration project.
- **Independent quality:** a genuinely independent evaluator with a frozen
  rubric and no access to the desired verdict.
- **Quality-preserving efficiency:** paired baseline/candidate runs with actual,
  comparable token usage and all protected checks passing.

Pending evidence is a release-note limitation, not permission to invent a result.
